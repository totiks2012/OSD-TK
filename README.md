# OSD — лёгкий текстовый OSD на Tcl/Tk

`OSD` — небольшой OSD-индикатор для Linux: показывает короткий текст поверх окон,
не забирает фокус и не требует демона уведомлений, D-Bus, `libnotify`, `jq` или
внешних рантаймов. Только Tcl/Tk и базовые системные утилиты.

Проект рассчитан на два сценария:

- самостоятельный CLI `osd`;
- необязательная интеграция с экосистемой `me` как метод `me osd`.

> **Важно про текст:** все текстовые каналы работают в UTF-8 (`stdin`, `--file`,
> временные файлы и внутренний реестр). Не пропускайте текст через
> `iconv -f ISO-8859-1 -t UTF-8` — это двойное кодирование и оно ломает кириллицу.
> Если видите «кракозябры», проверьте, что на входе настоящий UTF-8.

## Возможности

- показ текста из аргументов, `stdin` или файла;
- настраиваемые шрифт, цвета, отступы, позиция и размер окна;
- несколько независимых плашек одновременно;
- стек плашек в одной позиции: новая встаёт ниже предыдущей и не двигает её; 
- автоматический reflow при закрытии или истечении TTL;
- `state`-каналы: повторное уведомление с тем же `--key` обновляет существующую
  плашку и сбрасывает её таймер;
- режим `allow_multiple=0` — повторный вызов с тем же ключом заменяет плашку,
  а не создаёт новую;
- приоритеты, `sticky`, вытеснение по лимиту и переполнению экрана;
- `--kill` для закрытия всех плашек;
- `--dump` для проверки текста без открытия окна;
- копирование текста по ЛКМ в PRIMARY и CLIPBOARD;
- закрытие по ПКМ ;
- нет постоянного демона: пока плашек нет, нет ни одного процесса.

## Требования

- Linux с X11 или XWayland;
- Tcl/Tk 8.6+;
- `tclsh` в `PATH`;
- базовые утилиты: `mkdir`, `kill`, `mkfifo`;
- желательно `setsid` (пакет `util-linux`) для полного отделения плашки от терминала;
- опционально для клипборда: `wl-copy`, `xclip` или `xsel`. Без них используется
  встроенный Tk-selection.

Проверка:

```bash
tclsh <<'EOF'
puts [info patchlevel]
package require Tk
puts "Tk OK"
exit 0
EOF
```

## Установка

Самый простой вариант — просто скопировать файлы проекта в отдельный каталог:

```bash
mkdir -p ~/.local/bin/osd
cp osd.tcl osd.conf.example ~/.local/bin/osd/
```

Теперь движок лежит здесь:

```
~/.local/bin/osd/osd.tcl
```

Можно запускать по полному пути:

```bash
~/.local/bin/osd/osd.tcl "Привет"
```

### Симлинк: короткое имя команды

Чтобы не писать полный путь каждый раз, сделайте симлинк в каталоге, который
уже есть в `PATH`. Имя симлинка выбираете вы сами.

Пример: назовём команду `OSD`.

```bash
ln -s ~/.local/bin/osd/osd.tcl ~/.local/bin/OSD
```

Проверка:

```bash
OSD "Привет"
```

Что здесь важно:

- первый путь — куда вы скопировали `osd.tcl`;
- второй путь — будущее имя команды в каталоге из `PATH`;
- имя может быть любым: `osd`, `OSD`, `myosd` и т.д.;
- каталог, где лежит симлинк, должен быть в `PATH` (обычно это `~/.local/bin`).

Проверить `PATH`:

```bash
echo "$PATH"
```

В примерах ниже команда называется `osd`. Если вы назвали симлинк иначе,
подставляйте своё имя, например `OSD`.

### Конфиг

Имя файла конфига **не захардкожено**. Файл можно назвать как угодно и положить
в любое место. Главное — правильно указать путь в `--config`.

```bash
mkdir -p ~/.config/osd
cp osd.conf.example ~/.config/osd/notify.conf
$EDITOR ~/.config/osd/notify.conf
```

Запуск:

```bash
osd --config ~/.config/osd/notify.conf "Сборка завершена"
```

Второй вариант — вообще не указывать `--config` каждый раз. Тогда OSD ищет
конфиг сам, в таком порядке:

1. файл, который вы передали в `--config`;
2. путь из переменной окружения `OSD_CONF`;
3. `osd.conf` в текущем каталоге;
4. `osd.conf` рядом с самим `osd.tcl`;
5. встроенные значения, если ничего не найдено.

Поэтому можно положить конфиг рядом с движком:

```bash
cp osd.conf.example ~/.local/bin/osd/osd.conf
```

и запускать без флагов при прямом запуске:

```bash
~/.local/bin/osd/osd.tcl "Привет"
```

Если вы запускаете через симлинк (`OSD`, `osd` и т.п.), надёжнее указать
конфиг явно — через `--config` или `OSD_CONF`. Симлинк и сам `osd.tcl` могут
лежать в разных каталогах, и автопоиск «рядом со скриптом» зависит от того,
как именно запущена команда:

```bash
OSD --config ~/.local/bin/osd/osd.conf "Привет"

# или
export OSD_CONF="$HOME/.local/bin/osd/osd.conf"
OSD "Привет"
```

Или задать один общий конфиг через `OSD_CONF`:

```bash
export OSD_CONF="$HOME/.config/osd/notify.conf"
osd "Привет"
```

`--config` всегда важнее `OSD_CONF` и автопоиска.

## Быстрый старт

```bash
# аргумент
osd "Бэкап завершён"

# stdin
printf 'строка 1\nстрока 2\n' | osd

# файл
osd --file /tmp/message.txt

# проверка текста без окна
printf 'тест' | osd --dump

echo 'тест' | osd --config ~/.config/osd/notify.conf

# свой конфиг и время показа
osd --config ~/.config/osd/notify.conf --duration 5 "Готово"

# закрыть все плашки
osd --kill
```

### State-канал

Одна и та же плашка обновляется на месте, таймер перезапускается:

```bash
osd --key volume --kind state --duration 2 "Громкость 30%"
osd --key volume --kind state --duration 2 "Громкость 40%"
```

Второй вызов не создаёт новое окно.

### Замена вместо размножения

В конфиге:

```ini
allow_multiple=0
```

Тогда повторный вызов с тем же `--key` (для `event`-плашек тоже) заменит текст
существующей плашки и обновит её таймер.

```bash
osd --config ~/.config/osd/notify.conf --key build "Сборка: 10%"
osd --config ~/.config/osd/notify.conf --key build "Сборка: 50%"
```

Если `--key` не указан, используется ключ `default`.

## Как это работает

Постоянного демона нет. Каждый вызов создаёт отдельный процесс плашки:

```
клиент ──spawn──> процесс плашки (Tk) ──> окно
                        │
                        ├── свой конфиг
                        ├── свой таймер
                        └── свой управляющий FIFO
```

Координация раскладки идёт через общий атомарный реестр в
`$XDG_RUNTIME_DIR/osd-<tag>-v3`:

```
osd-<tag>-v3/
  panels/   # по файлу на плашку: позиция, размеры, порядок, pid, fifo
  fifos/    # управляющий канал конкретной плашки
  spool/    # временный текст и ack-файлы
  lock/     # короткий замок на время изменения реестра
```

Ключевые свойства:

- запись плашки пишется атомарно (`tmp` + `rename`);
- изменение реестра сериализуется коротким `mkdir`-замком;
- порядок задаётся `born_seq`, выданным под замком;
- плашка сама перечитывает реестр и двигается по сигналу `reflow`;
- мёртвые записи вычищаются лениво при следующей операции;
- при аварийном завершении запись может остаться до следующего события —
  это осознанный компромисс ради отсутствия следящего демона.

Реестр — внутренняя деталь реализации. Его формат и путь могут меняться между
версиями; не используйте их как стабильный API.

## Стек и раскладка

Плашки с одинаковым `position` образуют группу.

- `top-*` и `middle-*`: новая плашка встаёт ниже предыдущей;
- `bottom-*`: новая встаёт выше предыдущей (дальше от нижнего края);
- уже видимые плашки при добавлении новой не двигаются;
- при закрытии или истечении TTL нижележащие плашки пересчитывают позицию.

Отступ между плашками задаётся `gap`. Для одной группы желательно использовать
одинаковые `margin` и `gap`, иначе геометрия может выглядеть неровно.

Лимиты:

- `max_panels` — общий максимум одновременно видимых плашек;
- при превышении выбирается жертва: сначала с меньшим `prio`, затем более старая;
- `sticky=1` защищает от автоматического вытеснения;
- `min_show` запрещает вытеснять плашку раньше заданного времени;
- при переполнении экрана также срабатывает вытеснение.

ПКМ и `Esc` закрывают плашку сразу, `min_show` на них не влияет.

## Состояния и события

`--kind event` (по умолчанию) — новое уведомление, обычно новая плашка.

`--kind state` — состояние с ключом `--key`. Повторный вызов обновляет текст
существующей state-плашки и сбрасывает её таймер.

`allow_multiple` управляет только повторным использованием **event**-плашек:

- `allow_multiple=1` — новые плашки разрешены;
- `allow_multiple=0` — event-плашка с тем же `--key` заменяет существующую.

При обновлении state-плашки или замене по `allow_multiple=0` передаётся и
конфиг нового вызова. Если путь или содержимое конфига изменились, плашка
перерисовывается с новыми цветами, шрифтом и размерами, а позиция
пересчитывается. Старый конфиг не «наследуется».

## CLI

```
osd [--config FILE] [--file FILE|-] [опции] [--] [TEXT...]
```

| Опция | Описание |
|---|---|
| `--config FILE` | конфиг для этой плашки |
| `-f`, `--file FILE` | читать текст из файла; `-` означает stdin |
| `-` | читать stdin даже если это терминал |
| `--key K` | канал плашки, по умолчанию `default` |
| `--kind state\|event` | тип плашки, по умолчанию `event` |
| `--prio N` | приоритет вытеснения, больше — важнее |
| `--sticky 0\|1` | не вытеснять автоматически |
| `--duration SEC` | переопределить `duration` из конфига |
| `--min-show MS` | переопределить `min_show`, мс |
| `--dump` | напечатать принятый текст и выйти |
| `--kill` | закрыть все плашки |
| `-h`, `--help` | справка |
| `--` | конец опций; дальше текст может начинаться с `-` |

`--daemon` оставлен только для совместимости и ничего не запускает: постоянного
демона в этой архитектуре нет.

## Конфигурация

Формат — `key=value`, по одному на строку. `#` — комментарий. У каждой плашки
свой конфиг. При создании он читается один раз; при обновлении state-плашки или
замене по `allow_multiple=0` новый конфиг перечитывается и применяется.
Изменение файла без нового вызова на видимую плашку не влияет.

| Ключ | По умолчанию | Описание |
|---|---:|---|
| `allow_multiple` | `1` | `1` — разрешать новые плашки; `0` — заменять плашку с тем же `--key` |
| `duration` | `3` | секунды показа; `0` — до ПКМ/`Esc`/замены |
| `position` | `top-center` | `top-left`, `top-center`, `top-right`, `middle-left`, `center`, `middle-right`, `bottom-left`, `bottom-center`, `bottom-right` |
| `margin` | `10` | отступ от края экрана, px |
| `font` | `{DejaVu Sans} 14` | шрифт Tk: `{family} size [style]` |
| `bg` | `#1d2021` | фон |
| `fg` | `#ebdbb2` | цвет текста и рамки |
| `border` | `1` | толщина рамки, px |
| `padding` | `12` | внутренний отступ, px |
| `wraplength` | `640` | максимальная ширина текста, px; `0` — авто |
| `max_height` | `400` | максимальная высота окна, px; `0` — авто |
| `win_w` | `0` | фиксированная ширина окна, px; `0` — по тексту |
| `win_h` | `0` | фиксированная высота окна, px; `0` — по тексту |
| `shrink` | `1` | `1` — уменьшать шрифт/обрезать; `0` — не трогать |
| `min_font_size` | `8` | минимальный размер шрифта при `shrink=1` |
| `align` | `left` | `left`, `center`, `right` |
| `gap` | `8` | отступ между плашками в группе, px |
| `max_panels` | `5` | максимум одновременно видимых плашек |
| `min_show` | `500` | минимальное время показа перед вытеснением, мс |

Особенности:

- при `win_h > 0` высота берётся из `win_h`, а `max_height` не используется;
- при `shrink=0` `min_font_size` не используется;
- `win_w`/`win_h` включают padding и рамку;
- если `wraplength=0`, ширина ограничивается экраном.

## UTF-8 и кириллица

Текст передаётся как UTF-8 на всех этапах. Если терминал, файл или пайп отдают
UTF-8, ничего дополнительно кодировать не нужно.

Правильно:

```bash
printf 'Ноябрь\n' | osd
osd "Готово: 5 файлов"
osd --file /tmp/message.txt
```

Неправильно (двойное кодирование):

```bash
printf 'Ноябрь\n' | iconv -f ISO-8859-1 -t UTF-8 | osd
```

Проверить вход можно через `--dump`:

```bash
printf 'Проверка кириллицы\n' | osd --dump
```

Если в `--dump` текст нормальный, а в окне «кракозябры», проверьте шрифт:
не все шрифты содержат кириллицу. По умолчанию используется `DejaVu Sans`,
у которого она есть.

## Диагностика

```bash
# проверить, что Tcl/Tk работают
printf 'package require Tk\nputs OK\nexit 0\n' | tclsh

# проверить текст без окна
printf 'тест' | osd --dump

# принудительно закрыть всё
osd --kill

# посмотреть справку
osd --help
```

Если плашка не появилась:

- проверьте `DISPLAY`/`WAYLAND_DISPLAY`;
- запустите `osd --duration 1 "тест"` и посмотрите ошибки в терминале;
- проверьте, что `tclsh` и Tk доступны;
- проверьте, что конфиг читается и не содержит неизвестных ключей;
- удалите старые runtime-каталоги `osd-*` в `$XDG_RUNTIME_DIR`, если остались
  записи от убитых процессов.

Если плашки наслаиваются не туда:

- убедитесь, что у плашек одной группы одинаковые `position`, `margin` и `gap`;
- проверьте `win_w`/`win_h`: фиксированный размер участвует в раскладке.

## Ограничения

- Каждая плашка — отдельный Tk-процесс. Это даёт изоляцию отказов, но расходует
  память; поэтому есть `max_panels`.
- Позиционирование использует размеры основного экрана Tk. Мультимониторные
  раскладки и выбор конкретного монитора пока не поддерживаются.
- Нет очереди и истории уведомлений: это OSD, а не notification center.
- Нет D-Bus и интеграции с системными уведомлениями.
- После `kill -9` запись плашки может остаться в реестре до следующей операции;
  она будет вычищена лениво.
- При копировании через встроенный Tk-selection процесс-владелец клипборда может
  жить до `clip_ttl` (20 секунд) после закрытия окна.
- Wayland поддерживается через XWayland, поскольку Tk рисует X11-окно.

## Безопасность

- Текст не исполняется: он передаётся в Tk `label`.
- Конфиг — это `key=value`, без `eval`.
- Runtime-каталог создаётся с правами `0700`, записи и FIFO — `0600`.
- Каталог версионирован по uid; чужие runtime-каталоги не используются.
- Внешние команды ограничены фиксированными вызовами (`mkdir`, `kill`,
  `mkfifo`, `wl-copy`/`xclip`/`xsel`) без подстановки пользовательского текста
  в shell.

## Структура публикации

```
pub/
  README.md           # этот файл
  osd.tcl             # движок OSD
  osd.conf.example    # эталонный конфиг, не загружается автоматически
```

`osd.conf.example` — именно пример. Чтобы он применялся, скопируйте его в
`osd.conf` рядом со скриптом, передайте через `--config` или задайте `OSD_CONF`.

## Разработка

```bash
# синтаксис/справка
tclsh osd.tcl --help

# текст без GUI
printf 'тест' | tclsh osd.tcl --dump

# ручной smoke-тест окна
tclsh osd.tcl --config osd.conf.example --duration 1 "тест"
tclsh osd.tcl --kill
```

Автотестов пока нет. При изменении раскладки или реестра проверяйте вручную:

1. две плашки с одинаковым `position` встают друг под другом;
2. закрытие верхней сдвигает нижнюю;
3. `--kind state --key` обновляет ту же плашку;
4. `allow_multiple=0` заменяет event-плашку с тем же ключом;
5. `kill -9` плашки не ломает остальные;
6. кириллица отображается корректно без `iconv`.
